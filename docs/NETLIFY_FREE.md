# Netlify Free 飞书热点推送

此部署使用 Netlify 的 **Free** 套餐，不购买套餐、域名、数据库、付费插件或额外积分。官方当前每月提供 300 积分硬限额，耗尽后暂停，不自动扣费。云平台规则会变化，以创建时显示的 Free 套餐为准。

## 部署配置

导入仓库 `lilianwei0815-star/TrendRadar` 的 `master` 分支，读取根目录 `netlify.toml`。基础目录为 `cloud/netlify`，构建命令 `npm test && node probe.mjs`，发布目录 `public`，函数目录 `functions`。只需 Node.js 22，不安装第三方 npm 依赖。

构建时从 `config/hotspot.json` 与 `config/frequency_words.txt` 生成配置模块。保留原六类关注词、24 个屏蔽词，来源扩展至 16 个热榜/视频榜单，另增加网络热梗词组。空格短语按 AND 匹配，任一屏蔽词命中标题则排除，仍保留用户指定的“关注”“点赞”等屏蔽词。

## 创作选题分类与视频监测状态（2026-10-21）

正式消息按栏目聚合展示，隐藏空栏目，不为栏目设置必须达到的条数；若成功抓取但没有匹配内容，则不发送凑数消息。最多 60 条为单次处理上限，不是每期目标。

视频栏目按具体程度优先归类，同一视频链接只出现一次：

1. AI萌宠视频｜热门作品
2. AI短片｜热门作品
3. 视频爆款线索｜平台热门作品

B站热门与排行榜适配器提供视频直达链接、作者、来源中的播放/点赞文字及发布时间；只允许具有榜单来源、合法视频链接和数字热度信息的记录进入视频栏目。上榜证明热度线索，不证明是短视频、增长速度、低粉爆款或账号异常表现；这些限制会随内容标注。AI分类依据标题和简介，未逐条观看核实。

B站先读取公开原生榜单，聚合源作为备选；原生接口提供时展示精确统计和视频时长，同类中优先 10 分钟以内作品，游戏分区按原有游戏排除要求过滤。快手先解析官网首页公开热榜 JSON，聚合源作为备选。不复制用户登录状态，不修改来源提供的统计数字。

优先来源为抖音、小红书、哔哩哔哩、快手、微博。公开平台热搜不再强制命中旧关注词后才保留，未命中兴趣词的主题单列“短视频与社交平台热榜线索”，保留全部屏蔽词。主题搜索链接不冒充某一条视频，话题热度不冒充单条视频播放量。同主题多源合并时优先使用这些平台的链接，知乎、贴吧及新闻来源作为补充。

同一栏目内部轮流选取各优先平台的数据，避免一个平台的长榜单占满每期处理上限。数量仍随有效内容变化，不承诺每个平台固定推送几条。

小红书使用 60s 项目公开社区实例的热榜 JSON，来源及响应格式参考：
- https://docs.60s-api.viki.moe/344628918e0
- https://docs.60s-api.viki.moe/7306811m0

公开实例不保证稳定。Netlify 部署期间运行只读来源探测，`source-status.json` 公开记录版本、探测时间、各来源成功/失败及条目数量，不包含飞书地址、内部密钥或用户私密内容。探测不发送飞书；定时运行日志另外记录每个来源的获取、匹配、入选数。

**按最新要求暂不监测视频号及指定博主。抖音具体热门视频接口已准备，尚待 Key 和真实数据验收。** 现有抖音热搜仍单列话题，不能当成已接入爆款作品。

新适配器使用聚合数据“热门视频榜单”ID 573（https://www.juhe.cn/docs/api/id/573），官方分类页 https://www.juhe.cn/docs/3 当前标注免费 50 次/天。文档提供具体作品 share_url、author、play_count、digg_count、comment_count。只请求 hot_video 榜最多 50 条，每期一次，无重试、无付费备用；构建探测不调用此接口。不能证明全站覆盖、低粉爆款、实时增速或发布时间；必须在开通后检查榜单是否有当期作品，不把文档样例当作实时数据。

开通步骤：注册/登录聚合数据，在 ID 573 页面申请免费额度，按其要求完成账户验证；仅选择免费额度，不充值、不购买套餐、不启用付费续用。如果页面未提供免费选项，停止申请。将该接口专用 Key 填入 Netlify 项目环境变量 `JUHE_DOUYIN_API_KEY`（Functions 运行环境），不要发在聊天或写入仓库。重新部署后，手动运行定时函数并核对后台获取数量、实际作品和飞书收到的内容，才能验收。

抖音榜单中具有有效作品链接及完整数字播放/点赞/评论数、且通过现有排除词的作品优先保留，不与其他平台轮流竞争处理上限（最多 50 条，整体上限 60 条）。按标题归入 AI萌宠、AI短片、其他视频三个栏目，按来源标注数据。链接统一为抖音具体作品页，去除分享追踪参数。API Key 仅通过固定 HTTPS 服务端 POST 发送，不随错误或公开探测结果输出。数据源限额和准确性仍待真实调用确认。

在 Netlify 环境变量中设置：

| 名称 | 内容 |
| --- | --- |
| `FEISHU_WEBHOOK_URL` | 用户的飞书机器人地址，仅存于云端环境变量 |
| `HOTSPOT_INTERNAL_SECRET` | 独立生成的至少 32 字符随机内部调用密钥 |
| `JUHE_DOUYIN_API_KEY` | 可选；聚合数据 ID 573 的免费接口专用 Key，未设置时不请求 |
| `HOTSPOT_MODE` | 正式为 `normal`；`test` 只测试连接；`preview` 只抓取并在日志显示统计、不发送 |

密钥不要填写到 GitHub 文件、`netlify.toml` 或公开网页。Netlify 自动提供 `URL` 环境变量，用于定时函数调用同站点后台函数。

## 执行与验证

`hotspot-schedule` 使用 UTC `0 0,4,10 * * *`，对应北京时间每天 **08:00、12:00、18:00**。定时函数本身的 30 秒限时只用于启动后台任务，实际抓取和推送由 `hotspot-background` 执行，内部任务总网络时限为 240 秒；来源抓取阶段最多 90 秒，原文摘要阶段最多 75 秒，为飞书发送保留时间。内部调用使用 HMAC-SHA256 签名并检查时间戳，未经验证的调用不抓取、不发送。

部署成功后，在 Netlify 的 Functions 中手动运行 `hotspot-schedule`。定时函数日志中的“已接受调用”只说明后台任务已启动；必须同时确认后台日志 `delivered` 大于 0、飞书群收到正式热点内容，才算云端推送测试成功。随后还需核对至少一次按时自动触发。首次部署不会证明下一次定时任务一定成功。

后台函数遇到发送错误时会记录安全错误信息并结束，不抛异常让平台重发整份报告，避免部分消息已送达后自动重复发送。全平台失败则停止，不发送“暂无新闻”。失败运行需检查后台日志；平台的 HTTP 202 不代表消息已送达。

## 费用与限制

不启用付费计划。Free 每月 300 积分为账户共享，成功生产部署也消耗积分，避免频繁重复部署。默认 1 GB 函数按当前 10 积分/GB·小时测算：假设 31 天每天 3 次、每次 60 秒，后台计算约 15.5 积分/月；这是估算，不含构建、部署和其他项目用量。额度耗尽会暂停，仍需关注控制台用量。

只覆盖配置中的公开热榜，不等于全网全文或全部视频、低粉爆款账号监控。摘要优先使用来源描述、其次摘录原文 meta 描述；无法取得可靠中文摘要时明确标记摘要暂缺，不编造。每次至多 60 条匹配记录，单次同标题跨平台合并，不做跨天增量去重。第三方热榜、原文页面和飞书接口的可访问性须在实际云端测试。

云端验收前保留旧 GitHub 工作流用于排查；云端验收后移除旧工作流的 cron，保留手动调试入口，以免 GitHub 恢复后重复定时推送。
